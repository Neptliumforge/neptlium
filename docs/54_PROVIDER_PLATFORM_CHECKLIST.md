# Platform-Wide Provider Checklist

For every Neptlium surface:

- Web: make no unverified claims of provider partnership, live capability, custody, settlement or availability.
- App: consume Neptlium projections; never authorize from client state or read provider truth directly as canonical.
- Treasury: create governed organization intents/policies/approvals; provider execution stays behind API capability selection.
- Pay: orchestrate money movement without becoming the ledger.
- Admin: show provider evidence/health truthfully without allowing status edits to fabricate execution/settlement.
- Forge: expose stable Neptlium APIs/events/sandbox rather than provider-native privileged contracts.
- API: own privileged adapters, configuration, evidence normalization, idempotency and provider selection.
- Platform Core: own authorization, policy, canonical ledger, reconciliation and audit.

Across all surfaces: Circle = stablecoin/digital-money infrastructure; Alchemy = multi-chain observation/intelligence; Stripe = fiat/payment infrastructure.
