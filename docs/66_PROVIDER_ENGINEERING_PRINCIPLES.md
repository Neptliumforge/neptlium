# Provider Engineering Principles

1. Own the domain; rent the rail.
2. Normalize at the boundary.
3. Fail closed when authority/evidence is missing.
4. Make every economic command idempotent.
5. Treat timeouts as ambiguous until proven otherwise.
6. Treat provider events as evidence, not accounting.
7. Certify capabilities granularly.
8. Separate observation from execution.
9. Keep secrets and privileged SDK authority server-side.
10. Make settlement/reconciliation explicit.
11. Preserve append-only financial history.
12. Make provider replacement a boundary change, not a product rewrite.
13. Report configuration, capability and production truth precisely.
14. Never trade safety for a UI that merely appears functional.
