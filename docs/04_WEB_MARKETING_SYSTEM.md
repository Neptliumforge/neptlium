# NEPTLIUM Web Marketing System — Remediation Mode

## Purpose

`apps/web` owns public narrative, product explanation, SEO, and entry into the operating application. It does not own implementation status or financial authority.

## Current communication rule

During production remediation, Marketing may explain NEPTLIUM's intended capital operating model, but it must not state or imply that a financial capability is live merely because code, schema, provider integration, or UI exists.

Claims requiring production evidence include:

- live deposits or withdrawals;
- settled or reconciled balances;
- custody/provider relationships;
- execution capability;
- customers, AUM, transaction volume, performance, returns;
- licences, regulatory status, approvals, or partnerships.

## Product language

Public copy should describe the platform in terms of governed capital operations, evidence, control, visibility, and connected workflows without exposing internal remediation mechanics unless a status page or explicit technical document requires it.

## Remediation constraint

No public CTA or product page may direct users into an unproven real-money flow. If a capability is intentionally unavailable during remediation, the application must fail closed and Marketing must not imply immediate availability.

## Design authority

The visual direction remains product-led and institutional. Remediation does not require turning Marketing into an engineering dashboard. It does require factual accuracy.

## Final rewrite

After all production gates close, update this document again to align public capability language with the final verified production surface.
