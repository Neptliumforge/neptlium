# Provider Terminology

Use these terms consistently across code, documentation, product copy and operations.

**Provider** — external infrastructure supplying a bounded capability.

**Adapter** — Neptlium server-side boundary translating provider APIs/events into Neptlium contracts.

**Capability** — a specific provider/network/rail/environment/operation combination the platform can reason about.

**Configured** — required configuration exists and validates. Not a claim of availability or execution permission.

**Connected** — authenticated non-consequential provider communication has succeeded.

**Certified** — required engineering and operational gates for a capability have passed.

**Eligible** — the principal and contextual constraints permit the capability to be offered.

**Authorized** — Neptlium policy/risk/approval state permits a specific intent.

**Submitted** — Neptlium attempted or confirmed provider submission according to the operation contract.

**Observation** — external evidence from a provider or chain. Not canonical financial truth.

**Settlement evidence** — evidence relevant to a rail/network-specific settlement definition.

**Settled** — Neptlium settlement policy has been satisfied. Not automatically reconciled.

**Reconciled** — canonical Neptlium state and required external evidence agree under the reconciliation contract.

**Canonical ledger** — Neptlium-owned accounting authority for financial state.

**Provider balance** — external observation. Never synonymous with canonical available balance.

**Chain supported** — infrastructure can address a blockchain capability. Never synonymous with deposits/withdrawals/execution enabled.

**Execution-enabled** — a narrowly scoped capability has passed required gates and has explicit production authorization.
